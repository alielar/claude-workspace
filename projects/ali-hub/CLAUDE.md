## 1. What this is

Ali's private daily dashboard, used on an **iPhone, installed as a PWA**, every day. Single user; **Google sign-in is enforced live** (`AUTH_REQUIRED=1` on Vercel). Deployed on Vercel.

**The rebuild is a convenience problem first.** Phone first, instant open, works offline, dark + light, few sections. If a feature makes the app slower or heavier on the phone, cut the feature.

**Stack:** Next.js 16 (App Router, see AGENTS.md), Drizzle ORM + Turso (libSQL), Tailwind v4 utilities are available but the design system is hand-written CSS in `globals.css` + inline styles. Anthropic API (`claude-haiku-4-5-20251001`) for the few AI features. Vercel cron.

## 2. Acceptance gates (every phase, spec §3)

1. Phone first — thumb-reachable actions, ≥44px tap targets, single column on the phone.
2. Installable + offline — service worker, local-first data, never a hanging spinner.
3. Fast — usable screen under ~1.5s on a cold open; render the local copy first, refresh after.
4. Dark and light — follows the phone by default, manual override in Settings.
5. Simple — five tabs (Today · Train · To-do · News · Settings). Books, Mobility, Breathe and the Vault are reached from inside, not as tabs.
6. Links open externally — `target="_blank" rel="noopener noreferrer"`.

### Local-first data (`src/lib/local/`)
- `store.ts` — `useCached(key, fetcher, { merge? })`: paints the phone's saved copy instantly, refreshes in the background (on mount, on focus/foreground, after an outbox flush, and every 45 s while visible — cross-device sync), `setData` for optimistic edits, `markEdit()` to be called when a write has LANDED. Backed by localStorage (swap for IndexedDB in one file if a module outgrows it). Three guards against a stale answer reverting an edit (the "tick comes back, needs a second tap" bug, 2026-09-19 and again 2026-09-24): (1) a refresh that started before the last `setData`/`markEdit` is dropped, so a GET that raced the PUT never wins; (2) the service worker MARKS an API answer it served from its own cache (`x-ali-cache: 1`, `isWorkerCopy`) and the store only uses one when it has nothing local at all — before 2026-09-24 a slow GET (over the worker's 3 s timeout) came back as yesterday's list with a 200 and was believed, which is also why the laptop sat on old rows until a hard reload; (3) modules whose rows carry `updatedAt` pass `merge` (to-dos: `mergeTodos`, newer row wins per clientId, deletions kept as tombstones in `cc:v1:todos-gone`, rows only on the phone survive while their PUT is in flight or in the outbox).
- `outbox.ts` — `sendOrQueue(...)`: writes go straight to the server; if offline they queue and replay in order on reconnect. Entries have a `dedupeKey` so repeated taps collapse to the final state. **Every endpoint used through the outbox must be idempotent** (send the desired final state, never "toggle").
- `SyncOutbox` (in AppShell) replays on open / online / foreground and fires `cc:outbox-flushed`.

### Service worker (`public/sw.js`, registered by `SwRegister`)
- `/_next/static/*` cache-first · page navigations stale-while-revalidate · `GET /api/*` network-first (8 s) then cache, a cached answer carries `x-ali-cache: 1` and the late network answer still refreshes the cache · `/offline` fallback.
- Bump `VERSION` in `sw.js` when cache behaviour changes. Settings → "Update app" clears caches and reloads.

- Flat solid surfaces (no blur/grain/gradients), **system font** (`-apple-system…`, no web fonts), body 17px, card titles 15/600, captions 13–14 sentence case. Mono (`ui-monospace`) only for clocks/counters. One accent (`--violet`: #8B7CF0 dark / #5B4BD6 light) + semantic pos/warn/neg. `--accent-soft` for selected chips, `--on-accent` for text on the accent.

### Routine engine (Phase 2)
- Routine steps, habits and regular items are all **checklist items** with a `kind`: `routine` (counts toward the day's streak), `habit` (being built — own streak, not counted until promoted), `manual`. Promotion = set `kind` to `routine` in the editor.
- Built-in steps carry a stable `routineKey` and are seeded once by `GET /api/checklist` from `ROUTINE_SEED` in `src/lib/checklist/types.ts` (stretch, breathe, supp-am, supp-pm, read, gym-push/pull/legs, gym-kb). Never seed by title. **UNIQUE(user_id, routine_key)** (`DEDUPE_ROUTINE_ROWS` in the checklist route, also spread into migrate): two concurrent GETs used to seed the same step twice ("Push day showed two boxes"). A soft-deleted built-in keeps its key, so it never reseeds.
- **Everything on Today is editable on /checklist**: name, time of day, an optional clock time (`checklist_items.at_time` "HH:MM"), days of the week (`weekdays`, null = every day), counts-as (routine / habit / manual = "Extra"), note or link, delete (built-ins too). Setting a time also moves the item into the matching part of the day, so the two can never disagree; on Today's spine a timed step sits in that hour's segment in clock order, untimed ones above the timed rows. The column installs itself in the checklist route's `ensureColumns` (no migrate tap needed).
- **The editor reads `GET /api/checklist?all=1`** (cache key `checklist-all`): every active item with `hiddenToday`, so other weekdays' rows are visible and editable on any day (a plain GET returns today only · that hid the machine days from the editor on a Monday). "This week" card on top lists the day-specific items per weekday.
- Training days are checklist rows (`gym-*`, **never counted** · Today's `counted`, the widget and the server streak all exclude them): Sun push · Tue pull · Thu legs · Sat `gym-kb` "Kettlebell · KB Hour" (Train button → /train/kb1; ticks itself when a KB session is finished that day). The virtual Train row only appears when a KB session was done on a day with no gym row (no more "Rest day · Train anyway" filler). Today's MorningCard treats a machine day as a training morning.
- `/stretch` has a music library: 10 CC tracks (self-hosted in `public/music/`, list in `src/lib/routine/music.ts`; five Kai Engel epic-neoclassical pieces led by "Embracing the Sunrise", plus five other styles), preview + pick on the idle screen, plays looped at 0.35 vol during the session (pause/stop follows the timer). Movement names are spoken ONCE — at move start, never during rest.
- Mobility/breathe rows get an action button (`/stretch`, or the YouTube link opening externally). Finishing the timer ticks the item via the outbox. The checklist row's title lives in the DB (seeded "Mobility"; the migrate route renames an existing "Stretching" row).
- `src/lib/routine/stretching.ts` holds the movement list/timings; `cues.ts` the beep/vibration/voice cues (AudioContext must be armed from a tap).
- `/breathe` = technique picker + players. Picker: Wim Hof hero card (the daily) + 6 paced techniques from `src/lib/breathe/techniques.ts` (coherent, cyclic sighing, box, 4-7-8, alternate nostril, Kapalabhati), each row = goal · duration · honest 1-3 evidence dots; detail one tap deeper (pattern, copy, duration chips, Start). Generic player runs any step cycle (breath cues, hold countdowns, Kapalabhati snap-per-beat, nostril cues panned L/R); every finished session ticks the `breathe` item. Dizziness warning box (`DANGER_TEXT`) shows on Wim Hof + Kapalabhati before start.
- Wim Hof player: 3×30 breaths, 1:30 retention (tap ends it), 15 s recovery hold then **an 8 s long exhale before the next round — Ali's deliberate deviation from the standard protocol, never "fix" it back**. Hold tone = ONE constant oscillator (never two detuned — equal tones beat to silence) + 1 s watchdog against iOS audio interruptions, volume follows the slider; tones split into brainwave beats (6/10/40 Hz, headphones, some evidence) vs solfeggio lore, chosen PER ROUND (key `cc-breathe-freqs`, JSON array of 3; legacy `cc-breathe-freq` migrates to all rounds). Breath sound: 12 synthesized styles + volume (`cc-breathe-sound`/`cc-breathe-vol`); session screens show only Ali's top 5 (`cc-breathe-favs`, ★ in "All sounds", `SoundPicker`). Rising bell on the last 10 breaths of each round (one scale step per breath, G4 → B5). 3-2-1 countdown after Start in every player. Exercise demos: none (Ali wants precise motion or nothing, spec §7c item 13).

### Morning plan (`src/lib/morning/plan.ts`)
- The morning sequence and its clock: `trainWake` 06:00 / `restWake` 07:00 / `callsAt` 08:30 (the hard stop), then steps that stack from the wake time — wake 10 · Mobility 10 · Wim Hof 12 · Train 36 (`trainOnly`) · Shower 15 · Breakfast + podcast 25. `saturdayShiftMin` (60) moves the whole clock on Saturdays; `computeMorning(plan, isTraining, kind)` takes the `DayKind` and returns `timed: false` on Sunday. `shiftHM` is the one helper for shifting "HH:MM".
- Which wake time applies comes from whether today is a training day (`kb_workouts.assignedDays`, Settings → Training days). Every minute is editable in Settings → Morning routine and sticks in `user_settings.morning_plan`; `parseMorningPlan` falls back to `DEFAULT_MORNING_PLAN` on anything malformed and rewrites a saved "Stretching" label to "Mobility".
- Today's MorningCard renders it. If you change the default sequence, change it here — Settings and Today both read this one file.

### Apple Watch (spec §7c item 5 — receiving end built, UI pending)
- Source = **Health Auto Export** (HAE) Premium, REST API automations → `POST /api/health/ingest` (public in the proxy, checks `x-app-key: APP_KEY` itself, `?key=` fallback). iOS lets HAE read Health only while the phone is unlocked, so posts arrive at odd times and repeat the last days: **every write is an upsert** (night by wake day, workout by HealthKit `hk_id`, metric by day+name). The old Shortcut failed for exactly this reason (timed automation on a locked phone → empty data) — see `docs/apple-watch-sync-research.md`.
- `src/lib/health/types.ts` = pure parser (`parseHaePayload`, HAE dates "yyyy-MM-dd HH:mm:ss ±HHMM", mi→km, kJ→kcal, HR derived from a per-minute series when the summary is missing, empty nights dropped, `sleepScore` = A L I's own 0–100 since Apple has none). `src/lib/health/server.ts` = `HEALTH_DDL` (self-creating tables, also spread into the migrate route), `storeParsed`, `healthStatus`, `logRaw` (last 30 raw posts in `health_raw` for checking the real payload shape).
- Tables: `health_sleep` (minutes + stage minutes + score, UNIQUE user+date), `health_workouts` (type, duration, distance, kcal, hr avg/min/max, raw minus route/HR series), `health_metrics` (any HAE metric: resting_heart_rate, heart_rate_variability, heart_rate min/avg/max, respiratory_rate, blood_oxygen_saturation…).
- Settings → Apple Watch card: connection status (last sleep / workout / post), URL + key copy buttons, the setup steps. `GET /api/health/ingest` (signed in) feeds it.
- Where the data is shown (a Fitness merge of Train + health) is still open — **do not add a sixth tab**.

Tasks: **Notes** (row shows the first 3 lines, tap = all, tap = back · `NotesPreview`) or **Subtasks** (`- [ ] ` lines rendered as tick boxes under the row · `SubtaskList`, `SubtaskEditor` in `src/app/(app)/todo/notes.tsx`). All five share the same stored text so switching loses nothing.
- **A typed subtask is never lost** (2026-09-24): the add box commits on blur as well as Return, mirrors its draft into `draftRef`, and both sheets fold `withDraftSubtask(notes, draft)` in on Done or tap-away (`close` reads `dRef`, synced from state in an effect, not the render closure).
- **Ticking a subtask or checklist item REMOVES the line** after the animation (Ali: "if I click it done, remove it"); old `- [x]` lines still show struck through and go on tap; there is no "Untick all". A task's subtasks are a plain checklist — checkbox + full-width box per line, no ✕ and no ↑↓; Return anywhere jumps to the add box, which appends and keeps the caret there (an empty line cannot survive `parseSubtasks`, so a new item is always born in that box). `SubtaskEditor` takes `ordered` — **only the doc checklist passes it** and keeps ↑↓ and ✕, because a doc may hold real steps. ### Password vault — passwords, API keys, recovery codes, secure notes
- **Two doors**: the Google sign-in cookie (the vault API refuses `x-app-key` on purpose, 403) and a **vault passphrase that never leaves the phone**. `src/lib/vault/crypto.ts`: PBKDF2-SHA-256 600k rounds → AES-256-GCM, non-extractable `CryptoKey` held in a ref on `/vault` only. Server (`src/lib/vault/server.ts`, `/api/vault`) stores per user `vault_meta` (salt, iterations, verifier = encrypted constant) and per item `vault_items` (id, opaque blob, updated_at, deleted). Even kind and name are inside the blob; search/filter happen after decrypt.
- **Never cached**: `public/sw.js` skips `/api/vault`; the page uses plain `fetch` with `no-store`, not `useCached` → the vault needs a connection (deliberate: nothing, not even ciphertext, rests on the phone). Auto-lock 5 min idle / 60 s in background / Lock button. **No passphrase reset exists and none may be added** (a reset = the server can read the vault). Change passphrase = re-encrypt everything on the phone, `PATCH /api/vault`.
- CSV import (`csvToImportRows` in `src/lib/vault/types.ts`): header-matched (Chrome, Safari/iCloud Keychain, Firefox, Bitwarden, 1Password, KeePass), parsed and encrypted on the phone, deduped on name+username, sent in batches of 200. Common e-mails = most-used usernames (`commonEmails`) offered as chips. **Ali never pastes passwords in chat · import only.**
- **Backup / restore** · "Save backup file" writes `ali-vault-YYYY-MM-DD.json` = `{format:"ali-vault-backup", version:1, exportedAt, count, meta:{salt,iterations,verifier}, items:[{id,blob,updatedAt}]}` · exactly the server's ciphertext, useless without the passphrase. Handed over via the iOS share sheet (Web Share with files → Files/iCloud Drive/AirDrop/Mail), `<a download>` fallback. Restore: on the setup screen (fresh DB: POST meta + PUT blobs as they are, then unlock with the backup's passphrase) or inside an open vault (merge by id, newer `updatedAt` wins; a backup made with another passphrase is decrypted with it and re-encrypted with the current key). `cc-vault-last-backup` (timestamp only) drives the "last …/never" tail, amber after 30 days. A row "Copy" button copies the password / key / codes without opening the item.
- Honest limits (told to Ali): the JS is served by Vercel, so a compromised deployment could ship code that reads the passphrase (same trust model as Bitwarden's web vault); an unlocked phone with the vault open is the weakest link; copied secrets sit on the iOS clipboard (Universal Clipboard).

## 5. Rules

**Communication** — plain language, describe what the user sees, one-line "I decided X because Y" for judgement calls (spec §9).

**UI** — phone layout first, then widen. Every card: `.cc-card` + `.cc-card-head` + `.cc-card-body`. Use `—` or `.cc-skeleton` while loading, never spinners. No fixed pixel widths wider than `min(Npx, 100vw - 32px)`. No hover-only controls. Inputs ≥16px on the phone.

**Copy** — no em dashes in UI text, use `·` or a period. No emojis in UI labels (the `emoji` field on older `ROUTINE_SEED` rows is legacy data; new rows leave it empty). **No filler** (Ali 2026-09-24): no sentence that explains what a control does or how the app behaves · a label, a state, a value. Warnings and one-line instructions (an install step, an ISBN hint) may stay.

**Data** — optimistic updates with rollback; writes through `sendOrQueue`; reads through `useCached`. Idempotent endpoints with unique constraints + silent catch on duplicates.

**Performance** — no new dependency without a reason it can't be 30 lines of code. No client component that pulls a library into every route (`AppShell` must stay tiny). Check `next build` route sizes before shipping a phase.

**Read first** — `node_modules/next/dist/docs/` before any Next.js-specific code.

**Commits** — small, descriptive. After pushing, run `npx vercel --prod` (auto-deploy is not relied on).

**This file** — nothing prunes it automatically. When you add a line, look for the line it replaces. Record what the app *is*, not what changed on a given evening; the git log is the changelog.
